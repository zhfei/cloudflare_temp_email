# Cloudflare 临时邮箱 项目技术文档

## 1. 项目概述

**Cloudflare 临时邮箱 (Cloudflare Temp Email)** 是一个基于 Cloudflare 生态系统构建的免费临时邮件服务。该项目利用 Cloudflare Workers 的无服务器架构和 Cloudflare D1 (SQLite) 的轻量级数据库能力，提供了一个功能完整、性能极佳的临时邮箱解决方案。

项目主要旨在提供接收、查看及部分发送邮件功能，保护用户的真实邮箱不被泄露，支持用户注册与管理、自定义域名、多角色控制以及第三方/Passkey 登录。

## 2. 系统架构设计

本项目采用了完全的 Serverless 架构，彻底摆脱了传统的服务器运维负担。架构主要由以下几层组成：

*   **流量接入与网关层**：由 Cloudflare 强力驱动，所有的用户 HTTP 请求及邮件收发请求直接由 Cloudflare 边缘节点接管。
*   **前端展现层 (Frontend)**：基于 Vue 3 并在 Cloudflare Pages 上运行，通过 API 与后端交互。
*   **后端计算层 (Backend/Worker)**：运行在 Cloudflare Workers 上，处理所有的业务逻辑、API 请求、用户鉴权（JWT/Passkey）、邮件管理等。
*   **邮件解析与处理 (Mail Parser/WASM)**：利用 Rust 编译成的 WebAssembly (WASM) 模块，直接在 Worker 层高效解析原始邮件内容 (Raw Email)，性能极佳且占用资源极低。
*   **数据存储层 (Storage)**：
    *   **Cloudflare D1**：作为核心关系型数据库，存储用户、角色、邮件列表、邮件内容及系统配置等结构化数据。
    *   **R2 / KV / S3 (可选)**：用于存储大体积附件、缓存及验证码状态等非结构化数据。
*   **外部集成层**：
    *   **邮件路由 (Email Routing)**：利用 Cloudflare Email Routing 将收到的邮件路由转发至 Worker 处理。
    *   **SMTP Proxy**：Python 编写的代理服务，支持传统的 SMTP 协议发信以及 IMAP 查看（扩展能力）。
    *   **第三方服务**：Bot 通知 (Telegram)、Turnstile 人机验证、OAuth 登录等。

## 3. 技术栈选型

*   **前端应用 (Frontend)**：
    *   **核心框架**：Vue 3 + Vite
    *   **UI 组件库**：Naive UI
    *   **语言**：TypeScript
    *   **富文本编辑器**：WangEditor
    *   **国际化**：Vue I18n
    *   **PWA 支持**：Vite PWA Plugin
*   **后端服务 (Backend)**：
    *   **运行环境**：Cloudflare Workers
    *   **语言**：TypeScript
    *   **WebAuthn**：`@simplewebauthn/browser` (用于 Passkey 无密码登录)
*   **邮件解析核心 (WASM)**：
    *   **语言**：Rust
    *   **技术产物**：WebAssembly (`mail-parser-wasm`)
*   **外挂代理服务 (SMTP Proxy)**：
    *   **语言主要为**：Python
*   **核心存储驱动**：
    *   Cloudflare D1 (基于 SQLite)
    *   Cloudflare KV / R2
*   **基建与自动化**：
    *   **CI/CD**：GitHub Actions
    *   **部署平台**：Cloudflare Pages (前端) & Cloudflare Workers (后端)

## 4. 核心组件分析

### 4.1 Frontend (前端界面)
前端是一个标准的响应式单页应用（SPA）。具有以下核心模块：
*   **用户模块**：鉴权（密码、OAuth、Passkey）、多邮箱地址管理。
*   **邮件浏览**：实时信件列表、富文本邮件详情渲染、附件查看与下载。
*   **Admin 控制台**：供管理员配置黑白名单、系统参数、定时清理策略、全局域名配置以及查看用户状态。

### 4.2 Worker (后端 API)
`src/worker.ts` 是后端的统一入口，所有路由经过此类：
*   **API 路由分发**：处理前端各种 CRUD 请求，如获取地址、删除邮件、发送邮件等。
*   **Mail 监听器**：Worker 挂载了 `email` 触发器，被 Cloudflare Email Routing 调用入站邮件。
*   **Cron 触发器**：利用配置中的 `crons` 触发定时任务，如彻底清理过期邮件以及超出附件大小的冗余数据。

### 4.3 Mail Parser WASM (邮件解析)
传统 Node.js 邮件解析库在 Serverless 边缘节点上往往因为体积过大和单线程性能瓶颈受限。项目使用 Rust 编写邮件解析器，并打包为 WASM，直接与 Worker 运行时绑定。能毫秒级提取邮件的 Headers、Body、图片以及附件流。

### 4.4 SMTP Proxy Server
可选的独立 Python 服务器，用于将代理用户的传统 SMTP / IMAP 请求映射为后端 API 或 D1 操作，使第三方邮件客户端（如 Foxmail, Outlook）也能连接到该临时邮件系统。

## 5. 数据库设计 (D1 SQLite Config)

数据库基于标准的 SQLite 编写，核心表关系如下：

1.  **`users`**: 用户主表，记录 `user_email` 和密码 / 第三方绑定信息。
2.  **`address`**: 记录自动生成的临时邮件地址名称 (`name`)。
3.  **`users_address`**: 用户与临时邮箱地址的绑定关系 (1vN)。
4.  **`user_passkeys`**: 存储基于 WebAuthn 生成的 Passkey 凭据。
5.  **`raw_mails`**: 收件箱核心表，关联到发向某个 `address` 的原始数据 (`raw`) 和元信息 (`source`, `message_id`)。
6.  **`sendbox`**: 发件箱内容存储，同样关联到使用的发信 `address`。
7.  **`address_sender`**: 用于记录某个地址的发信额度 (`balance`)，防止滥用。
8.  **`user_roles`**: 用户角色权限划分表（如 admin、vip 角色），对应不同的专属域名及名称白名单。
9.  **`settings`**: KV 型键值对表，用于保存 Admin 面板中动态调整的系统配置。

## 6. 部署与配置机制

使用 `wrangler.toml` 进行环境声明与声明式基础设施部署：
*   **域名配置**：通过环境变量或 `DOMAINS` 和 `DEFAULT_DOMAINS` 支持多域名轮换。
*   **触发器限制**：可通过 `[[unsafe.bindings]]` 启用 Ratelimit 配置，防止批量自动化获取邮箱。
*   **安全凭证**：所有的安全 Token (JWT) 加密盐通过 `JWT_SECRET` 进行签名。
*   **多环境隔离**：开发环境下通过 `database_name = "dev"` 以及 `database_id = "local"` 实现与生产环境 D1 库的安全隔离。
*   **持续集成**：`package.json` 中的 `deploy` 相关脚本可配合 CI/CD 流水线，实现对 `pages` 以及 `workers` 的一键发布。
